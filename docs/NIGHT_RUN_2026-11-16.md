`/` (`apps/web/src/app/page.tsx`) renders the old page from
`features/academy/components/`. `/academy` (`app/academy/page.tsx`) renders the
Design System v2 page from `features/academy/v2/`. Swap them:

- **`/` renders v2** and keeps everything that `/` has today:
  - the full `metadata` (title template, keywords, Open Graph, Twitter,
    canonical `/`)
  - the JSON-LD `<script>`
  - `<AcademyHome />` together with the `platform-brand-only` wrapper (another
    academy's address must still get its own generic home)
  - `TrackingProvider`

    `ScrollObserver`. If it doesn't, leave them out of the v2 `/`.
- **`/academy` renders the old page.** Use `robots: noindex`, canonical `/` and
  no JSON-LD, which is what `/academy` has now. Move the old page body into a
  component (for example `features/academy/components/AcademyHomeV1.tsx`) so
  that both routes stay thin. **Delete no component, CSS or image.**
- Check everything that depends on either path:
  - `AppProviders.tsx` (it already special-cases both paths)
  - `routeAccess.ts`
  - `sitemap.ts`, `robots.ts` and `llms.txt`
  - the `/r/<code>` referral redirect

    the v2 page doesn't show; compare the JSON-LD facts with the v2 sections)
- Verify:
  - typecheck, lint, and a web build in the worktree
  - `npm run shots -- --path / --devices all --theme both`, then the same for
    `/academy`, with 0 horizontal overflow
  - no console errors with WebGL off and with reduced motion on
  - on an academy host (memory "backlog-gaps-tds-legal-pages" says how to view
    one), `/` still shows `AcademyHome`
- Branch `feat/home-v2-swap`. Update the BACKLOG entry from 2026-11-15

### 2. Storm/Racer: a puzzle that starts from the previous puzzle's position

the next solve isn't counted. Background: [BACKLOG.md](BACKLOG.md), the
2026-11-16 entry, point 4. Code: `features/puzzle-rush-solo/components/SoloRushPlayer.tsx`.
Check whether the live-class Storm player (`selectPuzzleRushRun` callers) has
the same bug.

- Fix it by keying the board reset on the puzzle id or index, not the FEN.
- Reproduce it first on a private stack with two seeded puzzles that share a
  start position, then confirm the fix there: both mates must count.
- Find out whether real catalogue puzzles ever repeat the previous start FEN in
  a run. Run a read-only query on `vps_dev`, and record the answer.
- Branch `fix/puzzle-rush-same-start-fen`. If the live-class player has the bug
  too, fix it in the same PR.
