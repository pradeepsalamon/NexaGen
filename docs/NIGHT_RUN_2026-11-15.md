## Rules for the run

- **Nothing is merged into `main` or `dev`.** Code goes on a branch with a PR
  into `dev`, left open. Never push to `main`.
- **No production changes**: no deploy, no `.env`, no nginx, no production
  database writes. Reading production (logs, read-only queries, a dump) is fine.
- **This checkout stays on `dev`.** Staging serves its `apps/web/.next-build`
  and `scripts/nexa.sh restart stage` runs migrations from whatever is checked
  out. Do branch work in a `git worktree` (`.worktrees/<name>`, branch created
  with `--no-track`), and never run a web build in this checkout to "check"
  something.
- **Browser and e2e tests run against staging**, integration tests against a
  database whose name ends `_int`. Never print a secret; read them from
  `apps/api/.env` into shell variables.
- **No questions.** A doubt goes into [BACKLOG.md](BACKLOG.md) § "Questions for
  the owner" with the choice made, and the run carries on.
- **Images and assets are never deleted**, even when nothing uses them.
- The box is the production host (2 cores, 11 GB). Kill only by PID.

### 1. Tell the user when a save fails

Many `useMutation` hooks in `apps/web` have no `onError`, and `src/lib/api.ts`
only shows a toast for session expiry and network failure, so a refused save
looks like nothing happened. `ec3685cf` fixed three (WhatsApp connection, legal
pages, TDS settings); follow its pattern for the rest.

- Branch `fix/mutation-error-toasts`, PR into `dev`, left open.
- Read [UI_RULES.md](UI_RULES.md) first; toasts through `useToast()`.
- Leave the live-class room's mutations alone unless the fix is obviously safe
  there ([LIVE_CLASS.md](LIVE_CLASS.md): follow-up work never goes in a per-call
  `mutate(…, { onSuccess })`).
- Verify with typecheck, lint, and a web build **in the worktree**.

### 2. Find other stale tests, and run Safari's engine

One test was out of date after the redesign (fixed in `1cef180a`: the filter
bar now sits behind a "Filters" button whose panel opens outside `<main>`).
Read every spec for the same kind of drift and fix the test, not the app,
unless the app is really wrong.

Then the WebKit pass. WebKit can't run on the host (missing system libraries;
don't `apt install` on this box): use the image
`mcr.microsoft.com/playwright:v1.62.1-noble` with `--network host`,
`E2E_WEBKIT=1` and `--project=webkit`.
