## Rules for the run

- **Nothing is merged into `main` or `dev`.** Code goes on a branch with a PR
  into `dev`, left open. Never push to `main`.
- **No production changes**: no deploy, no `.env`, no nginx, no production
  database writes. Reading production (logs, read-only queries, a dump) is fine.
- **This checkout stays on `dev`.** Staging serves its `apps/web/.next-build`
  and `scripts/nexa.sh restart stage` runs migrations from whatever is checked
  out. Do branch work in a `git worktree` (`.worktrees/<name>`, branch created
  with `--no-track`), and never run a web build in this checkout to "check"
  something.
- **Browser and e2e tests run against staging**, integration tests against a
  database whose name ends `_int`. Never print a secret; read them from
  `apps/api/.env` into shell variables.
- **No questions.** A doubt goes into [BACKLOG.md](BACKLOG.md) § "Questions for
  the owner" with the choice made, and the run carries on.
- The box is the production host (2 cores, 11 GB). Kill only by PID.
