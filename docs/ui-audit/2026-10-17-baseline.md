## 3. Defects, prioritized

P1 = broken or misleading for users / accessibility failure. P2 = visible
inconsistency across many screens. P3 = local polish.

### P1

1. **Header title collides with the right-hand controls at tablet width** (768 px, e.g. coach "My Batches"): the title column is `auto` with `sm:max-w-none`, so it never truncates (`components/layout/Header.tsx`).
2. **Tables and toolbars clip their own content.** `/admin/batches` at 1366 px cuts the Actions column (the Delete button is half hidden). `/admin/users` at 320 px cuts the tab list ("Setting…") and toolbar ("View"). The card or table wrapper clips instead of wrapping or scrolling.
2b. **`/admin/attendance` 6-month trend table**: body cells don't line up with their headers ("Attended / Total" values sit under "Attendance rate"). Low attendance is drawn in danger red (reserved for destructive + LIVE), and the page uses a narrower container than every other admin page.
3. **Two `h1`s on every signed-in page**: the header renders the page title as `<h1>` and so does the page. Screen-reader users get two competing headings. On `/profile` the second `h1` is just the role label ("Student" / "Coach").
4. **Navigation is an off-canvas drawer at every width.** On a 1366 px laptop, reaching any of the 44 admin pages takes open-drawer → (expand group) → click. On phones the closed drawer's 20 px saffron tab covers the left edge of page content (visible over tables, cards and calendars in nearly every mobile shot). *Needs a decision — see §6.*
5. **Row actions off-screen on phones**: on coach earnings, history, presets, puzzles and students the row actions sit past the right edge of a sideways-scrolling table. There's no mobile alternative.
6. **Login**: 8 carousel dots are 8×8 px targets and come before the form in tab order (12 Tab presses to reach Email). Pages have two `h1`s and neither is the form's "Log in".

### P2

7. **Header titles, page titles, nav labels and browser tab titles disagree.** Examples: nav "Assignments" / header "Practice" / page "Assignments & Practice"; nav "Messaging Rules" / header "Messaging" / page "Messages"; header "Puzzle" on both the scoring and PDF-import pages; header "New" on new schedule. Tab titles come in eight formats ("Nexa Chess", "X", "X - Nexa Chess", "X - NexaChess", "X - Admin", "X - Admin | Nexa Chess", "X | Admin | Nexa Chess", "X - Coach Workspace"). 28 pages show only "Nexa Chess" (21 admin, 2 coach, 3 student, `/profile`, `/`). Root cause: no `title.template` in `app/layout.tsx`, and the header keeps its own hard-coded `pageTitles` map.
8. **Off-palette colours** (the four-hue rule): 375 raw Tailwind palette classes + 58 `dark:` overrides outside the exempt areas. Concentrated in `app/admin/attendance/**`, `features/attendance/**`, `components/ui/Calendar.tsx`, `DatePicker.tsx`, live-class `MeetingStatus` / `MeetingParticipants` / `MeetingPuzzlePanel`. Coach dashboard KPIs use purple/orange/pink. The two dashboards hand-roll KPI tiles instead of using `StatTile` / `KpiCard`.
9. **Monospace numerals**: `StatTile` sets values in `font-mono` ("0 days", "3 / 3", "1200"), which clashes with Outfit/Nunito and is the only monospace text on most screens.
10. **Empty states framed twice**: a dashed `EmptyState` box (`min-h-[300px]`) inside an already-bordered card (student practice, coach dashboard/schedule, smart revision). Elsewhere empty states are a plain centred sentence. There are three different treatments.
11. **All-caps labels**: table headers (`TableHead`), `KpiCard` labels, "SCHEDULE DETAILS" / "MOST MISSED THEMES" eyebrows, status badges ("ACTIVE"). They're harder to read and inconsistent with the sentence-case page titles.
12. **Dashboards prioritise noise**: coach shows 6 KPIs, 3 at 0, plus a full-width earnings card holding one number. Admin `/admin` is a single ~8,600 px page containing every analytics section, which duplicates the nine dedicated analytics pages. Smart Revision shows 8 KPI tiles with "Due today" twice.
13. **Redundant header CTA**: "Dashboard" button shown while on the dashboard. On auth pages the header shows a "Login" button and a centred "Login" title above the login form.
14. **Native `title=` tooltips**: 192 uses (UI_RULES requires `SimpleTooltip` on interactive elements).
15. **Ad-hoc radius / shadow**: 19 `rounded-md…3xl`, 21 `shadow-sm…2xl` in feature code.

### P3

16. Login form is a card inside a card; on 320 px "Create account" wraps alone.
17. "1 Students" pluralisation on batch cards. Archived batches are interleaved with active ones and still offer a primary "Schedule" button.
18. Coach schedule lists past approved requests above upcoming classes.
19. Puzzle Training leaves a large empty column beside the board at laptop width.
20. Text-only "View all" / "repeat" actions with no link affordance.
21. `SectionCard` collapse button has no visible tooltip label.
22. Logo image aspect-ratio warning.

## 4. Proposed design-system specification

This is not a new identity. The Royal Ink palette, Outfit + Nunito Sans and the
radius/shadow tokens stay. What changes is how consistently they're applied.

**Colour (unchanged values; usage tightened)**

| Token | Value | One meaning |
|---|---|---|
| primary | `#2447A0` | classes, scheduling, primary action, navigation surface |
| secondary | `#F4B63F` saffron | attention, practice & assignments, active-nav highlight |
| accent | `#1F9D78` | success, attended, live-and-healthy |
| warm | `#E0685A` | learning, courses, recordings |
| danger | `#CF2E2E` | destructive + LIVE only |
| ink / surfaces | `#172049`, `#F6F7FC`, `#FFFFFF`, `#EEF1FA` | text, page, card, soft |

Status uses `success` / `warning` / `info` (+ `-ink`). No raw palette classes or
`dark:` colour overrides outside the over-video/board exception.

**Type**

- Outfit for headings *and numerals*. Stats use `font-display tabular-nums`, not monospace. Monospace is kept only for FEN/PGN/notation, clocks and invoice numbers.
- Scale (rem, follows the user's text-size setting): page title `text-2xl/extrabold`, section `text-lg/extrabold`, body `text-sm–base`, meta `text-xs` muted.
- Sentence case everywhere: page titles, nav, tab titles, table headers, badges. No all-caps eyebrows.

**Layout and shell**

- One title per page: the page's `PageHeader` owns the `h1`. The header bar shows a non-heading location label derived from `navItems` (single source).
- `metadata.title.template = "%s | Nexa Chess"`. Pages export only their short name, matching the nav label.
- Header grid: title column `minmax(0,1fr)` with truncation at every width.
- Navigation (recommended, pending §6): a persistent rail at `lg+` reusing the existing deep-primary drawer styling. Drawer stays below `lg`. The edge tab handle goes away when the rail is visible, and on mobile the hamburger is the only trigger.

**Components**

- `StatTile`: one KPI primitive (absorbs the hand-rolled coach/admin tiles). Compact horizontal layout on mobile, display numerals, tone from the four hues.
- `EmptyState`: two variants — `inline` (no frame, inside a card) and `page` (framed, when the page has nothing else).
- `TableHead`: sentence case, `text-xs font-bold`. `DataTable` gets an opt-in stacked-card row layout below `sm` so row actions stay on screen.
- `Badge`: sentence-case labels.
- Auth: single card, header CTA hidden on auth routes, carousel dots ≥ 24 px targets and after the form in tab order.

**Principles**

1. The board is the product: chess surfaces get the visual weight, and chrome around them stays quiet.
2. One colour, one meaning. If a colour doesn't carry information, it's a neutral.
3. Every number earns its tile: zero-heavy KPI walls collapse into a summary line, and actions sit next to the data they act on.
4. Same name everywhere: a destination is called the same thing in the nav, header, page title and browser tab.
